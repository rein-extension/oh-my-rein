## Claude/Pi execution-time approvals

Local native-model tests used Claude Code 2.1.322 (`deepseek-flash[1m]`) and Pi 1.5.2 (`deepseek-flash`) with isolated Host state. Each worker paused before a file write; a scripted denial left the file absent, then a new turn in the same native session requested and received one scripted allowance. The exact file content, collected artifacts, durable decision and native operation outcome were verified. Claude used a native Bash permission request; Pi used its write tool through Rein's explicit tool-call extension. This installed Claude build did not expose Write; its live coverage uses Bash, while protocol fixtures cover Write requests.

Protocol and packaged-runtime tests cover both adapters: independent concurrent requests, ask/delegate routing, client reopen, lost decision acknowledgements, cancellation, expiry, duplicate callbacks, unsupported tools, and unknown effects after an allowed operation loses its process. Pi also requires matching native-session and gate-ready signals before any model prompt. These are scripted UI/protocol tests, not human desktop acceptance or injected real SSH partitions.

The reproducible opt-in test is `node scripts/live-tool-approvals.ts --allow-model-calls --adapter claude|pi --executable /path/to/cli`, plus the provider/model settings documented in the installation guide. It calls the configured model and uses temporary repositories.

## Conversation-based worker configuration

The shared tool catalog exposes `rein_worker_permissions` and `rein_worker_permissions_set` through Codex MCP, Claude MCP with native session receipts, and Pi's extension. Automated tests exercise all three interfaces without a shell tool, plus each worker's partial-update semantics, bound-target/adapter checks, revision conflicts, concurrent identical calls, Host identity replacement, cancellation before submission, old-runtime rejection, and lost acknowledgements with newer intervening settings. Existing queued/running/resumed sessions retain their pinned configuration.

Configuration changes are explicit main-agent requests, not human UI approval receipts. These tests cover protocol behavior and runtime identity, not an autonomous model interpreting every natural-language permission request or a real remote configuration update through each UI.

## Current permission hardening

Regression tests cover same-task unknown effects at enqueue, start delivery, user-review completion and queued decision delivery. Related Host snapshots are refreshed before new work or allowances; independent task execution and denials continue. Effects review preserves original Host evidence. New policies carry version 2; old unversioned queued runs and request hashes remain unchanged, and delegated allows require user review.

The native main/worker smoke driver now explicitly uses noninteractive fixture worker permissions (Claude bypassPermissions with Read/Bash; Pi read/write with toolApproval never). This headless test covers main lifecycle, not approval UI or installation defaults; native approvals have separate tests. `node scripts/live-harness-smoke.mjs --preflight-only --harness pi --executable /path/to/pi` checks adapter setup without calling a model. Use `--runtime-dir /installed/package/dist/runtime` to check the runtime installed from a candidate archive; live execution still requires `--allow-model-calls`.
